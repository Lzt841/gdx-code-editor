# 编辑器实现检查与改进路线

检查日期：2026-11-26。当前版本：`v1.5.2`；此前问题复核基线为 `v1.5.1`（`424b2d5`）。

本次复核覆盖核心文档、搜索替换、扩展生命周期、可见行渲染、构建发行路径和已有回归测试。
这里记录代码与验证中可确认的行为和限制；OpenGL 截图覆盖新增渲染组合，平台输入与触控仍需实机验证。

## 项目概况

- `core` 是 Java 8 兼容的 libGDX Scene2D 编辑器库；`lwjgl3` 和 `android` 提供集成示例。当前依赖 libGDX 1.14.0，测试使用 JUnit 4。
- 编辑器能力覆盖大文件分行渲染、增量高亮、结构/折叠、撤销、搜索替换、补全、导航、格式化、诊断动作和可卸载扩展；多数语言语义能力由宿主 provider 提供。
- GitHub Actions 持续执行核心测试、打包和桌面/Android 编译。新增无窗口 OpenGL 截图任务覆盖深浅主题、折行缩进、缩放和折叠尾部；真实 IME、触控和缩放手势仍需设备验证。
- 当前完整核心测试为 46 个测试类、573 项，其中渲染回归 43 项，全部通过；核心打包、本地 Maven 发布和桌面/Android 编译通过。
- 主要已知产品限制是正则搜索按行执行、内置导航按词匹配而非作用域解析，以及除 JSON 外的语义格式化/重构依赖宿主语言服务。

## v1.5.2 透明度与着色修复

| 问题 | 原因与处理 |
| --- | --- |
| 父容器淡入淡出或给编辑器设置颜色时，编辑器内容保持不透明 | `CodeEditor.draw` 忽略 `parentAlpha` 和 actor 颜色，文字、行号、空白标记、参考线、选区、波浪线和行内图片都直接使用样式颜色；现在每个颜色都乘以“actor 颜色 × parentAlpha”，不透明白色时保持原样式颜色 |
| 触控选择手柄和放大镜不跟随编辑器淡出 | 手柄绘制在舞台根节点的覆盖层上，不在编辑器的父容器里；覆盖层现在沿用编辑器最近一次绘制的着色 |
| 补全列表和悬停/参数提示面板同样忽略透明度 | 两个 Actor 现在在绘制背景和文字前应用自身颜色与 `parentAlpha` |
| 内置默认样式的绘制对象覆盖批处理颜色 | 改为与当前批处理颜色相乘，自定义皮肤与默认样式在淡出时行为一致 |
| 前一个兄弟 Actor 的批处理颜色泄漏进编辑器 | 绘制开始时设置编辑器自身着色，结束后恢复调用方的颜色 |

兼容性：行渲染回调期间的批处理颜色现在是编辑器自身着色，而不是前一个 Actor 遗留的颜色；需要随编辑器淡出的自定义图层应乘以 `batch.getColor()`。

## v1.5.1 缩放与文字效果修复

本轮复核聚焦渲染测量与绘制是否使用同一组几何数据。测试记录真实的图片矩形和字形顶点坐标及颜色，以下问题均先由失败用例复现，再修复。

| 问题 | 原因与处理 |
| --- | --- |
| 缩放后行内图片尺寸、命中区域和折行错误 | 图片宽度作为固定像素 advance，文字随缩放变化而图片不变；现在宽、高与基线偏移按 100% 缩放声明，测量、命中、折行和绘制统一乘以缩放比例，超高图片缩小后在列内居中 |
| 预缩放字体的行高偏小 | 行高计算除去了字体自身的缩放，绘制时却按“基础缩放 × 缩放比例”放大字形，导致相邻行重叠；改为使用字体在 100% 缩放下的实际行高 |
| 字体缺失字符的宽度与绘制位置不一致 | 测量忽略字体的 `missingGlyph`，备用宽度对字体基础缩放重复相乘；没有替代字形时 BitmapFont 跳过该字符，后续字形整体左移。现在测量使用替代字形及其 kerning，备用宽度只缩放一次，绘制时按测量宽度留空 |
| 渐变文字在 Tab、图片和自动折行后重新开始 | 每个绘制片段单独计算色带；现在按整个 token 的宽度分配色带，每个字形取其中心所在色带的颜色，伪粗体多次绘制保持同样的颜色 |

桌面示例的表情和富文本图片提供器本来就按 100% 行高生成固定尺寸，新语义下能随缩放正确放大，不会二次缩放。
隐藏窗口 OpenGL 参考截图在修复后重新生成并人工检查，1.25 倍缩放与折行面板显示正常。Android GPU、触控与输入法仍需实机验证。

## v1.5.0 渲染能力扩展

| 问题或能力缺口 | 处理结果 |
| --- | --- |
| 空格、Tab 和行尾空白不易识别 | 增加 ALL / TRAILING / SELECTION 空白标记、独立行尾空白底色和真实换行箭头；采用像素纹理绘制，无需字体提供特殊字形 |
| 缺少固定宽度阅读参考 | 增加多个列参考线，以空格 advance 为单位，跟随横向滚动和缩放；延续折行缩进不移动参考线 |
| 宿主扩展行背景或前景需要侵入内部绘制 | 新增有序的背景/前景行渲染接口，提供原始行列、显示行、折行片段、测量坐标与折叠尾部映射；支持注册、移除与回调期间的安全注册快照 |
| 装饰图形的画笔颜色恢复错误 | 原实现保留 `batch.getColor()` 的可变引用，设置装饰色后该引用也被改变；改为保存 packed color 值，修复背景、各类下划线、诊断波浪线和图片的状态泄漏 |
| 折叠尾部缺少诊断绘制 | 将可见尾部源文本接入诊断、空白标记和自定义行图层；人工合成的占位符仍只承担折叠提示 |
| 长行标记可能产生大量无效调用 | 利用已缓存的列宽前缀数组二分跳过横向隐藏前缀，只提交接近可视范围的标记；显示设置切换复用布局及高亮缓存 |

新增效果默认关闭，可通过共享 `CodeEditorSettings` 控制；主题构建器提供相应色彩，复制样式时按值复制新增颜色。
密码模式抑制空白相关效果和宿主行回调，避免暴露原始文本；只读/禁用模式继续提供阅读效果。
行渲染上下文为复用对象，仅在回调期间有效；宿主应在下一次 `act` 修改内容，不应在回调中改变 Batch 的矩阵、shader、混合状态或 begin/end 状态。

桌面与 Android 均提供 Rendering 样例及效果开关；`:lwjgl3:renderingSnapshot` 使用隐藏 OpenGL 窗口生成组合截图。
截图验证采用桌面 OpenGL，不能替代 Android GPU、输入法与手势的实机验证。
参考截图已加入 README 和 `images/rendering-effects.png`。自动化回归实际记录绘制调用，覆盖空间坐标、全量/行尾/选区模式、
换行与 EOF、折行、折叠尾部诊断、滚动和缩放、代理对及图片宽度、密码/只读/禁用、状态恢复、长行可视范围裁剪与共享设置。

当前折行模型会把部分连续空白保留在行尾，可能超过视口；标记按实际测量位置裁剪，未改变文本的折行和点击语义。
列参考线使用空格宽度，对比例字体表示视觉边距而非 UTF-16 字符列。折叠尾部沿用已有的修剪及最多 48 字符显示限制。

## v1.4.1 / v1.4.2 优化

| 问题 | 原有行为 | 处理结果 |
| --- | --- | --- |
| 长行上的密集正则替换重复分配整行缓冲区 | 每个命中都重建 Matcher；`appendReplacement` 先复制该命中之前的行首文本，缓冲区容量也按整行分配，命中较多时产生大量短命对象和重复复制 | 复用一个 Matcher，直接解析 Java 替换模板到与插入文本同量级的缓冲区；保留数字组、命名组、转义、未匹配组和非法模板回退行为 |
| 缺少替换路径基准与自动构建门禁 | 本地可运行位置映射基准，但密集替换没有可重复度量；仓库没有 GitHub Actions 工作流 | 增加热身后的中位数基准任务，并对 push、PR 和版本标签执行测试、JAR 打包及桌面/Android 编译 |

替换模板回归额外与 Java Matcher 比较多位数字组、转义和非法模板的结果，并验证 lookaround 捕获、无变化版本保留及撤销。
v1.4.2 修复首次 Linux CI 暴露的 `gradlew` 可执行位缺失。完整核心测试为 45 个测试类、530 项，核心构建和本地 Maven 发布、桌面与 Android 编译通过。
长行基准由 `:core:searchReplacementBenchmark` 提供；本机热身后中位数为
1,000/2,000/4,000 个命中约 6.1/7.8/7.2 ms，仅用于同机回归比较，不作为跨机器性能承诺。

## 本轮处理

| 问题 | 原有行为 | 本轮结果 |
| --- | --- | --- |
| 正则替换与输入过滤顺序错误 | 先过滤 `$1` 等模板，再展开捕获组；数字过滤器会把 `$1` 变成 `1` | 先展开每个匹配的替换文本，再对实际插入的字符过滤一次 |
| 相同内容替换污染历史 | 普通范围替换、批量替换和搜索替换仍执行删除及插入，改变版本、清空重做并触发内容事件 | 跳过最终文本相同的替换；全部无变化时保留光标、选区、折叠和历史 |
| 过滤回调后的状态未统一检查 | 普通替换可以在过滤器修改文档或切换只读状态后继续使用旧坐标 | 过滤结束后重新确认文档版本和编辑状态；拒绝外层过期操作 |
| 缺少行注释命令 | 宿主需要自行处理多行选区、前缀、撤销和快捷键 | 提供可卸载的行注释扩展，支持自定义前缀、反向选区和精确批量编辑 |
| 代码片段依赖文本发生变化才能启动 | 相同文本替换或空占位符可能无法启动；仅最终停靠点的完成状态依靠版本变化推断 | 复用已有文本进行占位符导航，显式区分插入失败和成功结束，保留历史与重做 |
| 片段正文和占位符映射脱节 | 字符过滤、CRLF 规范化或回调改写可能让占位符仍引用旧正文 | 同步规范化正文及偏移；插入前快照并验证模板，拒绝丢字符、代理对中点、非法重叠和循环依赖 |
| 镜像与嵌套字段跟踪不完整 | 相邻重复字符可能定位到错误副本；父字段覆盖后子字段仍可导航；子字段变化未同步祖先镜像 | 按实际编辑范围选择来源，清理被覆盖子字段；模拟子字段至祖先的传播，合并为一次精确批次和撤销步骤 |
| 延迟通知和重入事件使片段版本过期 | 同帧输入后立即 Tab 可能使用旧范围；递归通知可能先递送较新版本 | 内容事件携带前后精确范围及前版本；导航前刷新输入，校验版本链，保留上下区域独立编辑并结束不安全会话 |
| 缺少按词移动和删除 | 内置 `CodeKeymap` 将额外 Ctrl/Alt 回退到普通移动／删除 | 新增可选 `CodeWordEditingExtension`，支持 Ctrl/Option 键位、Shift 选区、Unicode 码点边界和单步删除撤销；默认键位保持不变 |
| 缺少大文件的位置映射索引 | `toOffset`、`lineAtOffset` 和 `columnAtOffset` 逐行扫描所有前置行；编辑后还要承担全量扫描成本 | 增加懒加载 Fenwick 行长前缀索引：首次查询后为 O(log lineCount)，同一行编辑增量更新，跨行结构编辑失效后按需重建；保留 UTF-16、换行边界和代理对行为 |
| 缺少保存状态 | 撤销／重做仍递增文档版本，单凭版本号无法判断内容是否回到保存点 | 提供 `isDirty()`、`markSaved()` 及异步快照重载；精确比较规范化内容，保存保留历史并终止连续输入合并 |
| 缺少行列跳转界面 | 只有宿主可调用的定位 API，越界坐标会被静默截断；无法直接通过键盘或触摸输入目标 | 新增可选 `CodeGoToLineDialog` 与作用域扩展，接入命令面板及 Ctrl/Command+G；严格校验 1-based 坐标，展开目标折叠并保护选区、历史及焦点生命周期 |
| 缺少格式化服务 | 宿主只能直接调用批量编辑，自行处理异步快照、过期结果、选区范围、过滤和撤销 | 增加可插拔的文档／选区格式化 provider、控制器和扩展命令；不可变快照、取消与版本守卫、精确批量编辑及单步撤销统一处理 |
| 过滤期间取消的工具仍可能提交 | 批量编辑只检查版本和只读／禁用状态，过滤器可以卸载扩展或取消异步任务后仍提交原结果 | 为精确批量编辑增加最终提交谓词；过滤只执行一遍，提交前再检查请求身份、生命周期、模式和版本 |
| 缺少开箱即用的格式化实现 | JSON 只有高亮和结构能力，格式化需要宿主另行接入 | 增加严格 JSON 格式化器，仅编辑 token 间空白，保留字符串转义、数字原文、键序和重复键；非法语法和过深嵌套整批拒绝 |
| 缺少诊断修复／代码动作服务 | 宿主需自行管理建议发现、预览、显式应用、过期结果及撤销 | 新增不可变代码动作模型、异步 provider、保留结果和整篇预览；显式选择后以精确批次提交，并提供按诊断 code 配置的替换规则和 Alt+Enter 扩展命令 |
| 文档版本不足以标识诊断批次 | 内容不变时新分析可覆盖诊断，旧修复仍使用相同文档版本 | 新增独立 `diagnosticRevision` 与诊断监听器；每次接受 set／clear 都推进修订，接收和提交前共同校验文档、诊断、光标、选区及请求身份 |

此前的行列跳转复用了定位、展开折叠和滚动能力，格式化服务进一步统一了快照、精确批量编辑与
作用域扩展生命周期。JSON provider 验证了语法检查、精细编辑和单步撤销的完整路径，默认同步运行，
大文档可由宿主 worker 执行并回到 GDX 线程提交。

本轮在此基础上增加诊断修复／代码动作：发现和预览保留建议，宿主选择后再显式提交；同时增加
独立诊断修订，避免同文档版本的新分析使旧修复继续有效。内置 provider 按 code 匹配规则并精确替换
诊断范围；选项列表和预览界面由宿主提供，跨文件修改和语言语义仍交给宿主解析器或语言服务。
跨行搜索会牵涉匹配模型、渲染片段、缓存失效和替换语义，本轮保留其现有逐行行为，留作独立改进。

过滤器自己修改文档的行为属于宿主回调；拒绝外层操作不会撤销回调自身产生的修改。
搜索范围仍沿用固定坐标语义，编辑后需要宿主重新设置。

| 高 | 桌面与 Android 输入验证 | 当前自动测试覆盖模型和部分 Scene2D 事件；仍需验证中文输入法组合输入、软键盘、手柄拖动、缩放及不同密度下的实际交互 |
| 中 | 跨行搜索 | 现有正则按行执行，不能跨换行匹配。若增加跨行模式，应明确增量缓存、全文件快照成本和零长度匹配语义 |
| 中 | 语言能力与重构精度 | 已有格式化与代码动作 provider、JSON 格式化及按诊断 code 的修复规则；其他语言的语义修复、导航与重命名仍需宿主解析器或语言服务，word navigation 不能区分同名变量的作用域 |
| 后续 | 块注释、矩形选区和多光标 | 本轮只提供行注释。块注释需要语言边界规则；矩形选区与多光标需要扩展单选区数据模型及批量光标变换，应单独设计 |

## 验证约定

- 内容修改应可撤销，并尽量作为一次命名操作通知宿主。
- 只读、禁用、密码模式及过滤器拒绝操作时，保留用户已有状态。
- 选区终点落在下一行第零列时，该行不属于整行编辑范围。
- 保留 UTF-16 代理对边界，区分逻辑文档行与自动换行后的显示行。
- 性能改进需要测量；仅凭复杂度分析不声称已经改善实际帧率。
